# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`fasti-kit` is a FastAPI starter kit built around a scaffolding CLI that generates DDD-style domain folders (routes/schemas/entities/models/repositories/services). Two domains exist today: `auth`, `user`. It's meant as a reusable project template, but it's grown well past a bare skeleton — it also carries production-shaped infrastructure (RFC 7807 problem details, primary/replica DB routing, a transactional outbox, a dead-letter queue, N+1 query detection, rate limiting, response caching, background jobs, cursor pagination, path versioning, `import-linter`-enforced layering) that new domains are expected to plug into rather than reinvent.

Keeping this file in sync: use the `/refresh-claude-md` skill (`.claude/skills/refresh-claude-md/`) to re-audit it against current repo state — don't hand-patch it piecemeal when drift is found.

Project skills in `.claude/skills/`: `/refresh-claude-md` (this file), `/scaffold-domain` (generate a new domain via the CLI, which wires it in itself, then add the migration and verify), `/check-all` (run pyright/ruff/lint-imports/deptry/pytest and report failures, no auto-fix), `/add-route` (route→service→repository wiring, resource-style URLs, auth/scopes, error handling, rate limiting), `/write-repo-method` (entity conversion, replica routing, cursor pagination conventions), `/write-test` (transactional `db`/`client` fixture conventions, runs the test after writing it). Workflow skills (auto-trigger, not task-specific): `/plan-before-code` (investigate + state scope before editing on nontrivial work), `/debug-root-cause` (reproduce first, root cause before fix, watch primary/replica routing), `/validate-before-done` (don't claim done unverified — run check-all, actually run tests, exercise routes), `/commit-style` (this repo's gitmoji convention, atomic commits, never auto-commit). `fastapi` and `library-skills` are third-party reference skills, not project conventions. If a skill and the Architecture section below disagree, the Architecture section wins.

Config comes from `.env` (see `.env.example` for the full key list — DB primary/replica URLs and pool sizing, `SERVER_HOSTS`, `ALLOWED_ORIGINS`, `JWT_SECRET_KEY`/`JWT_COOKIE_SECURE`, `JWT_REFRESH_TOKEN_TTL_DAYS`/`REFRESH_REUSE_GRACE_SECONDS` (see Auth), mail SMTP settings, Redis, `SHUTDOWN_TIMEOUT`, `FORWARDED_ALLOW_IPS` (commented out, so the environment-aware default applies), outbox/dead-letter/task-retry tuning, and a commented-out `API_UPSTREAM` for Caddy), loaded via `core/setting.py`'s `pydantic-settings` `Settings` (cached with `@lru_cache`, use `get_settings()` everywhere rather than instantiating directly). Real environment variables override `.env`, which is how the compose `app`/`devcontainer` services repoint the DB/Redis/mail hosts and how the test plugin repoints the run. `docker run --env-file` (unlike compose's `env_file`) keeps quotes and trailing spaces, which `.env`'s `JWT_ALGORITHM="HS256"` style values fail validation on — use `docker compose run`. Every DB URL must use `postgresql+asyncpg://` — there is no sync driver installed (Alembic's `env.py` uses `async_engine_from_config` too). `get_replica_url` falls back to `database_url` when `DATABASE_REPLICA_URL` is unset, so a deploy without a replica reads from the primary. `environment` is `local`, `staging` or `production`: `Settings.is_deployed` (anything but `local`) drives HSTS and JSON logs, the N+1 detector and the Caddy proxy trust default are `local` only, and `core/safety.py`'s `--allow-production` guard fires for `production` only, so staging stays seedable.

The app's OpenAPI title, summary and version come from the installed package metadata (`importlib.metadata.metadata("fasti-kit")` in `main.py`), i.e. from `pyproject.toml`'s `name`/`description`/`version` — change them there, not in `main.py`.

## Architecture

### Domain-per-folder DDD

Each domain (`auth/`, `user/`) is a top-level namespace package (no top-level `__init__.py`) with up to six identically-named subpackages, each with its own `__init__.py` that re-exports its symbols (kept up to date by the scaffolding scripts, not hand-maintained imports):

- `entities/` — plain `@dataclass` domain objects (DB-agnostic), e.g. `user/entities/user.py`
- `models/` — SQLAlchemy `Mapped`/`mapped_column` ORM classes bound to `core.database.Base`
- `repositories/` — DB access layer; takes an `AsyncSession` in `__init__`, returns entities (not models) to callers, converts via a `_to_entity` static method
- `schemas/` — Pydantic request/response models for FastAPI
- `services/` — business logic, orchestrates repositories, called from routes
- `routes/` — `APIRouter` instances, aggregated into `core/api_versions.py`'s `v1_router` (mounted at `/api/v1`), which is included once in `main.py`

Layers are called through each other in one direction: route → service → repository → model, with entities as the return type crossing back up. Routes get dependencies via `Depends()` factories in each domain's `dependencies.py` (e.g. `user/dependencies.py`'s `get_user_service`, `get_current_user`; `auth/dependencies.py`'s `get_auth_service`, `get_auth_session`) rather than constructing `Service(Repository(db))` inline.

**Who owns what** (a decision recorded in `docs/reliability-scalability-maintainability-review.md`):

| Layer | Owns | Must not |
|---|---|---|
| Route | Parsing, validation, calling one service method, shaping the response (cookies, status) | Take `db`, commit, hold business rules |
| Service | Business rules, orchestration, hashing, token creation, cache invalidation | Touch the session, commit, raise `HTTPException` |
| Repository | All DB access, **the transaction**, primary/replica pinning, turning `IntegrityError` into `ConflictError` | Hold business rules |

- Every public repository method is one atomic unit: it wraps its writes in `async with transaction(self.db):` (`core/database.py` — commits on success, rolls back on error). There is no `auto_commit` flag and no caller-side `db.commit()`.
- `stage_*` methods (`UserRepository.stage_add`/`stage_update`/`stage_deactivate`, `RevokedTokenRepository.stage_add`/`stage_add_if_absent`, `RefreshSessionRepository.stage_revoke`/`stage_revoke_all_for_user`, `OutboxRepository.stage_add`) flush without committing. They are building blocks for another repository method's transaction only — a service calling one directly would silently write nothing, and the `stage_` name is the guard.
- A flow that writes several tables is a single repository method, not several service calls: `UserRepository.register` (user + verification jti + outbox row), and `auth/repositories/account_repository.py`'s `AccountRepository` (verify-email, reset-password, start email verification / password reset, logout, close account — spanning `users`, `revoked_tokens`, `refresh_sessions` and `outbox_events`). It lives in `auth` because `auth` may import `user.repositories` but not `user.models`.
- Read-after-write freshness is `consistent=True` on `UserRepository.get`/`get_by_email`, which pins the read to primary. Routes and services never touch `force_primary_var`; repositories set it themselves before writes.
- Below the route layer, raise `DomainException` subclasses (see `core/exception.py` below), never `HTTPException`. The `Depends()` guards do too: `get_current_user` raises `EntityNotFoundError`/`UnauthorizedActionError`, `require_scopes` raises `UnauthorizedActionError`.

This layering is not just convention — `pyproject.toml`'s `[tool.importlinter]` has six contracts, run via `uv run lint-imports` (also a pre-commit hook):
1. one-way `routes → services → repositories → models` layers per domain (`containers = ["auth", "user"]`, `exhaustive = false`);
2. entities forbidden from importing `sqlalchemy`/`fastapi`/`pydantic`;
3. `auth` forbidden from importing `user.routes`/`user.services`/`user.models` directly (`allow_indirect_imports = true` on purpose — `auth → user.repositories → user.models` is a structural chain that can't be removed, so don't delete or tighten it);
4. `auth` forbidden from reaching `user.routes` even transitively;
5. `*.routes` and `*.services` (plus `core.dead_letter.router`/`.service`) can't import `sqlalchemy` or `core.database`;
6. `*.services` and `*.repositories` (plus `core.dead_letter.service`/`.repository`) can't import `fastapi`.

`core.dead_letter.*` is named explicitly in 5 and 6 because the `*.routes`-style wildcards don't match its flat module names. Nothing restricts the other direction between domains: `user` currently imports `auth` (`auth.dependencies.auth` for token guards, `SecurityService`/`EmailVerificationService` in `UserService.register`, and `AuthService` for `DELETE /users/me`).

**URLs are resource-style.** Plural noun for the collection, `/{id}` for one record, `/me` for the caller's own record, HTTP method for the action — no verbs in paths. `user_router` (prefix `/users`): `POST /users` (register, rate-limited), `GET /users` (cursor-paginated list, `admin:read` scope), `GET`/`PATCH`/`DELETE /users/me`. Non-CRUD actions like `/auth/login` are the exception.

**Scaffolding CLI (`scripts/`)** — one generator path. Each `create_<layer>.py` has a pure `generate_<layer>(domain, name, fields)` function that holds the template and returns the paths it touched, plus a thin typer `create_<layer>` wrapper (prompts, validation, `ruff` via `format_paths`) registered as a `uv run create-*` console script in `pyproject.toml`'s `[project.scripts]`. Orchestrators (`create_all`, `create_test`) call only the pure functions — calling a typer-decorated function directly hands it `OptionInfo` defaults, which is what broke `create-all` before. `scripts/_boilerplate.py` holds the shared helpers: case conversion, a naive `pluralize` (appends `s`; used for both the table name and the URL prefix, so `category` → `categorys`), name validation (lowercase identifiers only; `RESERVED_DOMAINS` = `alembic`, `core`, `docs`, `main`, `scripts`, `tests`), `write_new_file` (skips existing files), an `ast`-based `update_init`/`merge_imports`, and the idempotent wiring helpers `register_pyproject` (adds the domain to all seven pyproject lists that name domains, verified with `tomllib`, never touching the auth-only contracts), `register_model` and `register_router`. Generated code follows the conventions above: repositories pin `force_primary_var` on writes, wrap each write in `transaction()`, translate `IntegrityError` to `ConflictError` in `_flush_or_raise`, and expose a cursor-paginated `list`; services raise `EntityNotFoundError` for missing records; routes live under `/<plural>` (`POST`/`GET /products`, `GET`/`PATCH`/`DELETE /products/{id}`), get the service from `<domain>/dependencies.py`, and require an access token on create/update/delete. Covered by `tests/test_scaffolding.py` (incl. a check that every console script resolves) and `scripts/smoke_scaffold.sh`.

### Request pipeline (`main.py`)

Middleware order matters. Starlette runs the last `add_middleware` call outermost, so `main.py` adds them as `GZipMiddleware`, `SecurityHeadersMiddleware`, `CorrelationIdMiddleware`, `N1DetectorMiddleware`, `CORSMiddleware`, `ProxyHeadersMiddleware`, and a request passes through them in the reverse order — proxy headers first, GZip last:
- `ProxyHeadersMiddleware` (uvicorn's, applied in the app rather than by the server) — rewrites `request.client`/`scheme` from `X-Forwarded-For`/`-Proto` only when the TCP peer is in `settings.forwarded_allow_ips` (`FORWARDED_ALLOW_IPS`, comma-separated IPs/CIDRs/`*`, each entry validated in `core/setting.py`). When the key is unset the default is `127.0.0.1,::1`, plus compose Caddy's `172.28.0.10` when `ENVIRONMENT=local` (a `model_validator` keyed on `model_fields_set`) — a host-run app sees Caddy as that bridge IP, not loopback, so without it every client shares Caddy's rate-limit bucket. Production keeps loopback only; an explicit value is used as given. It must stay outermost so the rate limiter and logs see the real client. Uvicorn's own proxy layer is disabled (`proxy_headers=False` in `main.py`'s `uvicorn.Config`, `--no-proxy-headers` in the `Dockerfile`) so this is the single trust source — don't re-enable it or set `--forwarded-allow-ips`.
- `CORSMiddleware` — `allow_origins=settings.allowed_origins`, credentials allowed.
- `N1DetectorMiddleware` (`core/middlewares/n1_detector.py`, **local environment only**) — counts queries per request via SQLAlchemy `before_cursor_execute` events, sets `X-Query-Count`, logs a warning above `threshold=10`.
- `CorrelationIdMiddleware` (`core/middlewares/correlation.py`) — generates/propagates `X-Request-ID`, and catches middleware-stack crashes and returns RFC 7807 JSON.
- `SecurityHeadersMiddleware` (`core/middlewares/security_headers.py`) — HSTS when `settings.is_deployed`.
- `GZipMiddleware` (`minimum_size=1000`).

Exception handlers are installed via `install_problem_handlers` (`core/problem.py`) and `install_auth_error_handlers` (`auth/errors.py`) — every API error path, including validation errors, rate-limit 429s, `DomainException`s and unhandled 500s, is normalized into a single `ProblemDetails` (RFC 7807 / `application/problem+json`) shape with a `correlation_id`. `core/openapi.py`'s `setup_openapi` replaces FastAPI's schema builder (it passes `title`/`summary`/`version`/`description` through explicitly, so a new `FastAPI(...)` info field must be added there too) and types every 4xx/5xx response as `ProblemDetails`; `problem_responses(*codes)` declares them per route. `prometheus-fastapi-instrumentator` exposes `/metrics`. `add_pagination(app)` enables `fastapi-pagination`.

Routers included in `main.py`: `health_router` (`core/health.py`: `/health/live`, `/health/ready` which probes primary DB, replica DB and Redis with 2s timeouts, and `/health/workers` which probes the SAQ worker, the outbox relay's Redis heartbeat (written by `relay_loop` after each successful dispatch) and the age of the oldest pending outbox row (`OutboxRepository.oldest_pending_age`, via the request's injected session) against `outbox_max_lag_seconds` — kept separate from `/ready` so a dead worker doesn't pull API instances out of rotation), `dlq_router` (`/api/admin/tasks/dlq`) and `v1_router` (`/api/v1`).

Startup runs `check_database`, `check_mail_config`, `check_jwt_config` (`core/startup_checks.py`) inside the `lifespan` and refuses to boot if any fail. Shutdown disposes the DB engines and closes Redis, each in its own try so one failure doesn't skip the other; `SHUTDOWN_TIMEOUT` is uvicorn's graceful-shutdown window. Under `__main__`, `main.py` builds a `uvicorn.Config` and runs `uvicorn.Server(config).run(sockets=bind_sockets(...))` — because the sockets are pre-bound, uvicorn doesn't print its "running on" line, so `core/dev_server.py` logs `Listening on http://…` per address instead.

### `core/` — cross-cutting infrastructure

- **`core/database.py`** — `AsyncResilientRoutingSession` auto-routes `SELECT`s to `replica_engine` and writes to `primary_engine`, "stickies" a request to primary for the rest of its lifetime once any write happens (via the `force_primary_var` contextvar; a `before_flush` listener sets it for ORM flushes too), and fails over reads to primary on a replica `OperationalError` — including `scalar()`/`get()`, not just `execute()`, and only when the session holds no pending/dirty/deleted objects a rollback would destroy. Both engines are built at import time from settings. `transaction(db)` is the commit/rollback context manager repositories use. `get_db` yields a session via `db_session()`, which resets `force_primary_var` per request. `AsyncSessionLocal()` is also opened directly, outside request DI, by `auth/dependencies.py`'s `is_token_revoked` (fallback and reseed only), `core/worker/tasks.py`, `core/outbox/relay.py` and `core/dead_letter/hook.py`. `bind_override_var` is a test-only escape hatch (see Testing).
- **`core/exception.py`** / **`core/problem.py`** — `DomainException(detail, status_code, type_str, title)` and its subclasses `EntityNotFoundError` (404), `UnauthorizedActionError` (403), `ConflictError` (409), `BadRequestError` (400); `auth/exceptions.py` adds `InvalidCredentialsError` (401), `InvalidRefreshTokenError` (401, `errors/invalid-refresh-token`) and `InvalidTokenError` (400). Raised in services, repositories and `Depends()` guards; `core/problem.py` turns them into RFC 7807 responses with `type` set from `type_str` (e.g. `errors/conflict`).
- **`core/cache.py`** — `@cache(ttl=..., tags=[...])` decorator for Redis cache-aside on functions with a return type annotation (required — used to build a `TypeAdapter` for serialization); `invalidate_tags(...)` wipes everything tagged. No function uses `@cache` today; `tests/test_cache.py` covers it. Don't cache entities that hold secrets — a cached `User` would put `password_hash` in Redis.
- **`core/queue.py`** / **`core/worker/`** — `task_queue` (saq/Redis) for background jobs; register new job functions in `core/worker/main.py`'s `functions` list (today `process_welcome_email`, `send_email_task`). Enqueue through `enqueue_task(name, key=..., **kwargs)` rather than `task_queue.enqueue` directly — it applies the project retry policy (`task_max_retries` / `task_retry_delay` / `task_retry_backoff`), without which SAQ's `retries=1` default means a job never actually retries. The worker's daily cron jobs purge revoked tokens (03:00), expired refresh sessions (03:15), dispatched outbox rows (03:30) and retried dead-letter rows (04:00). The worker calls `setup_logging()` at import (replacing the `basicConfig` saq's runner applies first), and its `before_process` hook `_bind_job_correlation_id` sets `request_id_context` to the job's `key` (e.g. `outbox:42`, `cron:cleanup_outbox_task`), so every line of one job — including the dead-letter hook's — shares a correlation id.
- **`core/outbox/`** — transactional outbox. `OutboxRepository.stage_add(task_name, payload)` records a queued task as an `outbox_events` row inside the calling repository's transaction instead of enqueueing directly, so the side effect commits atomically with the business write (repositories hold their own `OutboxRepository`; `get_outbox_repository` injects one into `/health/workers`). `relay_loop` (spawned in the SAQ worker's `startup` hook) polls with `FOR UPDATE SKIP LOCKED`, forwards rows to `task_queue` with a deterministic `key=f"outbox:{id}"` for at-least-once delivery, and parks poison rows in `failed_at` after `outbox_max_attempts`. A failing poll is retried forever; `_log_relay_failure` logs the full traceback only on the first failure of a streak, then one-line `still failing (N in a row)` warnings, then `recovered after N failed iterations` — so a worker started before migrations (e.g. `relation "outbox_events" does not exist`) heals itself without flooding the logs. `cleanup_outbox_task` purges dispatched rows past `outbox_retention_days`. Anything that needs an email sent goes through an outbox row, not `BackgroundTasks`. The relay's `dispatch_pending`/`cleanup_dispatched` call `db.commit()` directly — they sit outside the domain layers.
- **`core/dead_letter/`** — dead-letter queue for background jobs that exhaust their retries, laid out like a domain (`entity`, `model`, `repository`, `service`, `schema`, `router`, `dependencies`) plus `hook.py`. `record_dead_letter` is wired as the SAQ worker's `after_process` hook; when a job's terminal status is `FAILED`/`ABORTED` it writes the function, kwargs, traceback and attempt count to `dead_letter_jobs`. `dlq_router` (`/api/admin/tasks/dlq`, gated by `require_scopes("admin:read")` on the router, plus `admin:write` on retry/delete/purge — the reference for the scope-guard pattern) lists / inspects / retries / deletes / purges rows; `DeadLetterJobService` holds the rules and raises `EntityNotFoundError` / `ConflictError` (retrying twice) / `BadRequestError` (unbounded purge). Retry is one `DeadLetterJobRepository.retry` transaction: a conditional `UPDATE … SET retried_at WHERE retried_at IS NULL` claims the row (so concurrent retries get one 200 and the rest 409 — verified with 10 real connections and across three app replicas) and stages an outbox row with payload `{"kwargs": …}` — wrapped so stored kwargs named like SAQ `Job` fields still reach the task — which the relay enqueues with `key=f"outbox:{id}"` on its next poll. `cleanup_dead_letter_task` purges retried rows past `dead_letter_retention_days`. Not captured: jobs aborted by SAQ's `sweep` (worker hard-killed mid-job).
- **`core/limiter.py`** — `slowapi` `Limiter` backed by Redis, keyed on `get_remote_address`; apply with `@limiter.limit("5/minute")` under the route decorator, with `request: Request` as a parameter (every `auth_router` route except `/logout`, plus `POST /users`). `headers_enabled=True` means slowapi also needs a `response: Response` parameter to inject its headers — a limited route without one returns 500 *after* its write commits. `tests/test_rate_limit_headers.py` runs the limited routes with the limiter on to catch a missing one. The key is the client IP after `ProxyHeadersMiddleware` (see Request pipeline); behind a proxy that isn't listed in `FORWARDED_ALLOW_IPS`, every client shares the proxy's IP and the limits become global. Caddy overwrites a client-sent `X-Forwarded-For` with the TCP peer, so clients can't rotate buckets through it. Most HTTP tests set `limiter.enabled = False`; limiter tests share Redis buckets by IP, so `tests/test_proxy_headers.py` uses a random `2001:db8::/32` address per request source.
- **`core/migration_lock.py`** — `migration_lock(connection, log)`, used by `alembic/env.py`'s `run_migrations`: a session-level `pg_advisory_lock`, committed right after it's taken (alembic's `begin_transaction()` won't commit a transaction it didn't open, so without that commit every migration rolls back silently), released on success and dropped with the connection on error or crash. Waiters log `Another process is running migrations, waiting for it to finish`. Offline (`--sql`) mode takes no lock.
- **`core/deprecation.py`** — `route_class=DeprecationRoute` + `@deprecated(sunset=...)` marks a route deprecated in OpenAPI and injects `Deprecation`/`Sunset` response headers. No route uses it today; `tests/test_deprecation.py` covers it.
- **`core/safety.py`** — `ensure_safe_operation(...)` guards destructive/dev-only CLI commands (e.g. `seed --reset`) from running against production without an explicit `--allow-production` flag; also warns on non-local DB hosts outside production.
- **`core/logging/`** — one stdout handler, no log files. `build_logging_config(json_logs, echo_sql)` is the pure config; `setup_logging()` applies it with `json_logs = settings.is_deployed` (`JsonFormatter`: one JSON object per line with `timestamp`, `level`, `logger`, `message`, `correlation_id`, `exception`, plus any `extra=` fields) and `echo_sql = DB_ECHO`. SQL echo goes through the `sqlalchemy.engine` logger level, not `create_engine(echo=...)` — `echo=True` adds SQLAlchemy's own handler, duplicating every statement and breaking the JSON stream. `main.py` passes `log_config=None` to `uvicorn.Config` so uvicorn doesn't overwrite this config. Correlation id on every line via `RequestIdFilter`. Rotation is the log driver's job: every compose service uses the `x-logging` anchor (`json-file`, 10 MB × 3).
- **`core/factories/`** — polyfactory factories (used by `seed`, `create-factory`, tests).
- **`core/models.py`** — manifest-only: imports `Base` and every domain's models so `Base.metadata` is fully populated for Alembic autogenerate and app startup. When adding a new domain with its own models, import it here too (`create-all` does it for you).
- **`core/setting.py`** — `pydantic-settings` `Settings`, cached via `get_settings()`. `backend_url` gets an auto-prepended `http://` scheme if none is given. `server_hosts` (validated as IPs, exposed as `server_host_list`) and the environment-aware `forwarded_allow_ips` default live here; `DOCKER_BRIDGE_HOST_IP` / `COMPOSE_CADDY_IP` name the two compose-coupled addresses.
- Also: `core/dev_server.py` (`bind_sockets`, see Commands), `core/mail.py` (SMTP sending), `core/redis.py` (shared pool + `close_redis`), `core/api_versions.py` (`v1_router`, `API_V1_PREFIX`).

### Auth (`auth/`)

Uses `authx` (`auth/dependencies.py` configures `AuthX` with `JWT_TOKEN_LOCATION=['headers', 'cookies']`, HS256, `JWT_COOKIE_CSRF_PROTECT=True`). Access tokens travel via `Authorization: Bearer` header; refresh tokens are set as an HTTP-only cookie via `auth.set_refresh_cookies`. `auth/routes/auth_router.py` covers `/login`, `/refresh`, `/logout`, `/verify-email`, `/resend-verification`, `/forgot-password`, `/reset-password`; each calls one `AuthService` method (`auth/services/auth_service.py`). Token minting and cookie setting stay in the route. `require_scopes(*scopes, all_required=True)` (`auth/dependencies.py`) wraps `auth.token_required` and checks `TokenPayload.has_scopes`; scopes are stored space-delimited on the user row, exposed as `User.scope_list`, and embedded into the access token at login/refresh. Scopes mean grants *beyond* a normal user: a new user has none (`''` default), ownership of `/me` comes from the token's `sub`, and the only scopes in use are `admin:read` and `admin:write` (`seed`'s admin gets both). `get_auth_session` collects the access token's and (if present) the refresh cookie's `jti`/expiry and `sid` into an `AuthSession` for logout and account closing.

**Refresh tokens rotate, with reuse detection** (decision record in the review doc, "What changed on 2026-11-02"). Each login creates a `refresh_sessions` row (`RefreshSessionRepository`); the refresh JWT carries `sid` and `gen` claims and its `exp` is the session's absolute `expires_at` (login + `JWT_REFRESH_TOKEN_TTL_DAYS`, also fed to authx), so rotation never extends a session. `/refresh` calls `AuthService.refresh`, whose `rotate` is a compare-and-swap (`UPDATE … SET generation = generation + 1 WHERE id, user_id, generation, revoked_at IS NULL, expires_at > now`), and sets a new cookie (which also replaces the CSRF cookie — clients must reread it). On a failed swap the service decides: `gen` one behind and rotated within `REFRESH_REUSE_GRACE_SECONDS` → 409, nothing revoked (two tabs racing); otherwise reuse → revoke the session, log a warning, `InvalidRefreshTokenError`. That decision lives in the service with separate repository calls on purpose — a revoke inside a transaction that then raises would roll back. Logout revokes the cookie's session; reset-password and close-account revoke all the user's sessions in the same transaction. Access tokens from a revoked session stay valid until they expire (15 min) — checking `sid` per request is not done (it would need a Redis round trip of its own beyond the blocklist `MGET`, or a DB read). Refresh tokens without `sid` are rejected. authx pitfall: `TokenPayload.extra_dict` is always empty (it reads `__dict__`); custom claims are in `payload.model_extra` — use `refresh_session_claims(payload)`.

Auth persists its own state: `auth/entities/models/repositories` hold `RefreshSessionRepository` (above) and `RevokedTokenRepository`, the latter used both for logout/delete token revocation by `jti` (inserts use `ON CONFLICT DO NOTHING`, so revoking an already-revoked token is a no-op) and for one-time email-verification / password-reset tokens (a verify/reset token is inserted into the same revoked-token table once consumed, so replay is rejected; a newer request supersedes an older link via `pending_verification_jti` / `pending_password_reset_jti` on the user). `is_token_revoked` is registered as authx's blocklist callback and asks `TokenBlocklist` (`auth/blocklist.py`, Redis only) first: one `MGET` of `auth:blocklist:jti:<jti>` and `auth:blocklist:ready`. Ready present → the answer is final, no DB session opened. `ready` absent (Redis lost data) or any `RedisError` → the callback falls back to `RevokedTokenRepository.exists()` (pinned to primary, the old behaviour) and, if it wins the `auth:blocklist:seeding` `NX` lock, reseeds Redis from `list_active()` and sets `ready` last. The DB stays the source of truth: `AuthService.logout`/`close_account` call `blocklist.revoke` **before** the repository transaction (Redis failure fails the logout; a DB failure after it leaves the token blocked but unrecorded — both safe). One-time verify/reset jtis are still checked against the DB only (`AuthService._decode_one_time`). Redis must not evict keys (compose has no `maxmemory`; it runs `--appendonly yes` to shrink the crash-loss window to ~1 s). `tests/conftest.py` clears `auth:blocklist:*` and sets `ready` around every test, so a test that inserts a revoked row directly in the DB won't be seen by the route — go through `blocklist.revoke`. Auth reads user data through `user`'s `UserRepository` rather than owning user storage; `AccountRepository` (see Architecture) owns the cross-table writes.

Password hashing is `bcrypt` via `auth/services/security_service.py` — `hashpw`/`checkpw` require `bytes`, so `hash_password`/`check_password` encode/decode at the boundary; don't pass `str` into the bcrypt functions directly. Both are async and run bcrypt in a worker thread via `asyncio.to_thread`, so a hash doesn't block the event loop — `await` them. `_DUMMY_PASSWORD_HASH` is computed with the sync `_hash` at import time.

**Login enforces identical failure responses.** `SecurityService.authenticate` returns `None` for unknown email, wrong password, inactive or unverified account, and `AuthService.login` turns every `None` into the same `InvalidCredentialsError` (401, `Invalid credentials`). An unknown email is still checked against a precomputed `_DUMMY_PASSWORD_HASH`, so response timing doesn't leak whether the account exists either. Preserve both properties when touching login. `/resend-verification` and `/forgot-password` follow the same shape: they return an identical generic message regardless of whether the email exists.

### Testing (`tests/`)

**Isolation from dev data.** `tests/isolation_plugin.py` is loaded with `-p tests.isolation_plugin` in `pyproject.toml`'s `addopts`, so its `pytest_load_initial_conftests` hook runs before `conftest.py` and before any app module builds an engine. It sets `DATABASE_URL` and `DATABASE_REPLICA_URL` to `<db>_test` (idempotent — an already-`_test` URL is kept) and `REDIS_DB` to `TEST_REDIS_DB` (default 15, refused if equal to the dev `REDIS_DB`), then clears the `get_settings` cache. It imports `core.setting` inside the hook, not at module level — a module-level import runs before pytest-cov starts and drops coverage. `tests/conftest.py` then refuses to run if either engine isn't on a `_test` database (check with `-p no:tests.isolation_plugin`). Result: even code that opens its own session (worker tasks, lifespan, health probes) and every Redis user (limiter, cache, relay heartbeat, SAQ queue) stays off the dev data; `tests/test_isolation_plugin.py` covers the helpers and the switch.

`tests/conftest.py` provides `db_engine` (creates `Base.metadata` in the test database — no mocking, no testcontainers despite that dep group existing), `db` (builds the real `AsyncResilientRoutingSession` with `bind_override_var` pointed at the test connection, wrapped in an outer transaction + SAVEPOINT via `join_transaction_mode="create_savepoint"`, rolled back at teardown even though repositories call `commit()`; inside the fixture every `AsyncSessionLocal()` session also binds to that connection, so worker tasks and hooks called from a test roll back too), `client` (an `httpx.AsyncClient` against the ASGI app with `get_db` overridden by an async generator that resets `force_primary_var` per request, and `auth.dependencies.AsyncSessionLocal` patched so the token-blocklist check hits the test session), and `query_counter` (counts SQL statements executed during a test, for asserting no N+1 regressions — pair with `X-Query-Count` for manual checks against the dev server). Any test that writes must take `db`; a test without it that commits through `AsyncSessionLocal` would leave rows in the test database for later tests. Autouse fixtures dispose the Redis pool and the primary/replica engine pools after every test (asyncpg/redis-py bind connections to the event loop that created them, and pytest-asyncio gives each test a fresh loop). `pyproject.toml` sets `pythonpath = ["."]` and `asyncio_mode = "auto"`. Because the shared test connection hides a missing commit, `tests/test_transaction_ownership.py` counts `commit`/`rollback` calls directly. Middleware/handler tests (`test_security_headers.py`, `test_deprecation.py`, `tests/core/test_problem.py`) build a standalone `FastAPI()` with `TestClient` instead of using the fixtures.

Known sharp edge: a test that starts a background task on the shared `db` session must `await` the task after cancelling it, or the fixture closes the session mid-commit (`IllegalStateChangeError`) and the next DB test fails with `PendingRollbackError` — that was the old heartbeat/cleanup-test "flake". When testing a log line emitted after an `await` (e.g. the relay's recovery message), poll `caplog.messages` rather than signalling from the patched function, or the assertion races the log.
